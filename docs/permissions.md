# 用户与角色权限

在「用户 → 角色」配置角色模板，或在用户编辑窗口配置单个账号。
新建任务、媒体助理、任务记录、专家、技能、连接器、云端协同、控制及管理功能均有独立权限。

每项功能按实际支持的操作提供查看、使用／执行、新增／导入、编辑／配置、删除、共享／发布、导出／下载等选项。
勾选单个操作时界面会同时选中该功能的查看权限；取消查看会一并取消该功能的操作权限。
菜单和页面按功能权限显示，后端接口及终端、浏览器、桌面、手机的实时连接另行校验操作权限。
没有管理权限的用户仍可获取聊天所需的已授权模型、存储选项等基础信息。

- 旧版 `experts` 等模块权限继续代表该模块原有全部操作。编辑权限时会展开为具体操作，取消单项操作后不会留下隐藏的旧模块授权。
- `token_usage.all` 必须单独授权；旧版 Token 统计权限不会扩大为全平台统计。导出还需要导出权限。
- ACP 协作和公共资源管理可授权给自定义角色。公共资源的专家、技能、连接器上架／下架分别授权。
- 用户资料编辑、重置密码、角色管理及分配权限分别控制。非管理员只能分配自己已有的权限。
- 安全防护可授予完整编辑权限，或分别授权人工审批、文件访问、敏感信息、命令防护、技能扫描策略。
- 聊天选择技能、连接器、知识库时检查使用权限；没有使用权限的功能不会作为默认选择启用。
- 权限不会替代资源归属检查。已有的本人资源、共享资源规则继续生效；本版本没有新增部门数据范围。
- 角色仍是授权模板：应用角色时复制权限到用户，修改模板不会自动覆盖已经应用该模板的用户。
- 管理员始终拥有全部权限；需要限制能力时使用普通账号或自定义角色。

升级到数据库版本 24 时，为已有普通用户和角色保留原来不受菜单权限限制的新建任务、媒体助理、任务记录、云端协同及工作区文件入口。
该迁移只执行一次，之后撤销的权限不会在重启时恢复。SQLite 和 PostgreSQL 使用相同的授权规则。


## 可直接使用的角色模板

启动升级后，在“用户 → 新增用户”的角色下拉框直接选择以下模板：

| 角色 | 适用范围 |
| --- | --- |
| 媒体使用者 | 聊天、附件、使用专家/技能/连接器/知识库、管理自己的任务记录和工作区文件、查看本人用量。 |
| 媒体创作者 | 使用者全部权限，以及维护自己的专家、技能、知识库、媒体助理和定时任务。 |
| 资源运营员 | 创作者全部权限，以及资源共享、公共资源上架下架、查看全平台用量。 |
| 平台运维员 | 基础使用权限，以及模型、存储、插件、安全策略、通道、云端协同、终端、浏览器、远程桌面和 ACP 协作。应只授予可信运维人员。 |
| 管理员（已有） | 全部权限，包括用户和权限管理。 |

业务模板不授予用户和角色管理权，也不改变资源所有权规则。模板首次启动时写入数据库，可自行调整或删除；再次启动不会覆盖修改，也不会重新创建已删除的模板。已有用户不自动获得新模板权限。选择角色会复制当时的权限，后续修改模板不会自动同步到已有账号。
